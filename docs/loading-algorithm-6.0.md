# 装柜规划 6.0：算法、数据与执行边界

## 1. 唯一业务输入

本次计算以网页当前填写的产品数量、每箱数量、外箱尺寸、包装方式、托盘尺寸和工程参数为准。不存在按 SKU 编码自动纠正 EA/BOX 的产品目录。更改 EA/BOX 必须触发新计算，并进入保存、分享和报告快照；不能复用旧计算结果。

商品名称、代码、系列仅作为标识；修改这些文本不重新运行重型几何搜索。数值搜索由独立 Worker 执行，以输入键拒绝过期回包。保存/打印预检须比对当前计算快照。

验收脚本没有内置业务订单；必须显式读取网页输入快照。单元测试中的产品和数量仅用于回归，不是生产默认值或企业订单。旧验收资料已移出交付目录，保留在本地忽略目录以便追溯，不会部署。

## 2. 数量与尺寸

- 订单量模式保持用户输入件数；箱数 = ceil(件数 / 每箱件数)。非整箱仍使用完整外箱尺寸，只在最后一箱标记实际件数。
- 柜容反算仅修改被允许优化的数量；固定项保持不变，同组齐套满足相同件数及上下限。搜索结果不是全局数学最优证明。
- 长宽高以毫米计。箱高向上，仅允许底面 90° 旋转。设计外廓包含输入的箱差、托盘歪斜和间隙，画面与校验使用同一模型。
- 有效长 = 内长 − 门端预留；有效宽 = 内宽 − 两侧预留；有效高 = 内高 − 顶部预留。有效尺寸不是 ISO 外部尺寸。门洞另外检查，箱内静态可放入不等于整垛搬运路径已通过。
- 默认间距是可调整的工程控制初值，不宣称来源于行业大数据。必须按实测尺寸、箱体鼓包、包装材料和装卸方式复核。

## 3. 纸箱排布与余量

比较 SKU 顺序、两种底面方向、逐垛容量和纵向交错排布。候选优先减少柜数，再减少内部空隙与占长；逐项独立检查坐标边界、间隙、重叠、箱高、箱数和件数守恒。

不足一垛及尾箱优先在门端处理；门端不是额外强制预留一条整幅空带。散箱沿实际剩余阶梯形边界集中，不能回缩到完整高垛之间形成深井。混 SKU 同垛仅在完整底面支撑、隔离层厚度和高度满足时形成有条件候选，明确标记尚未验证承压。纸板/PE 膜仅用于隔离，不能自动视为结构承重材料。

空隙审计扫描各实际宽度/高度切片，分别报告内部空隙、门端自由空间、最大局部连续空隙和整幅门端净余量。不能将狭窄切片余量当作全宽可用长度。因包装尺寸、公差、必须间距及数量形成的空隙不会被隐藏，也不宣称全部可填满。150 mm 只是工具复核提示阈值，不是统一安全认证。

## 4. 塑料托盘与双层

单托先按允许承载面排箱，校验退边/允许外伸；再枚举最低至最高组托高度间的整数层数，比较单层、双层托盘。排序为：地面托位较少 → 托盘数量较少 → 整垛高度较低。该层数推荐是在当前单层排箱模式和输入约束内选择，并非所有立体打托方法的穷举证明。

底层托盘顶面必须满层、平整；尾箱或不完整顶面禁止直接承托上层托盘。每层实际箱数、顶层缺口及实际高度独立展开；末托不按满托画成虚构箱数。标准组托三视图明确标识为满垛模板；实际末托数量以整柜实景和末托顶面图为准。

双层方案必须补充托盘额定载荷、实际接触支撑、纸箱堆码抗压、湿度/运输周期影响和现场装卸条件批准。几何校验通过不等于承压已验证。包装材积中的托盘数值为各托标准组托设计包络的保守计划材积，不等于末托实际货物实体体积。

## 5. 三维、三视图和 PDF

`lib/cargoGeometry.js` 将同一排布逐箱展开到坐标、实际件数和各托盘层级。网页实时画面、正交三视图及报告快照共同使用这一模型，禁止再按总数量画近似色块。

不加载集装箱框架、侧墙或顶棚。纸箱按设计外廓等比例呈现，表面使用 MEGEE 标识、SKU 标签和实际 EA。尾箱为红色封带。塑料托盘外尺寸随输入；内部模具结构仅用于识别，不是实物结构图。

打印预检等待整柜四视图及每款托盘三视图完成。报告图像保持纵横比，表头重复、行不拆分、文字不以暴力压缩缩小。现场执行记录使用一致的签字线和页底规则。手机将输入表转为卡片，报告宽表在局部滚动，不撑宽整页；尺寸和状态标签放在图外，避免遮住货物。

## 6. 不能由软件替代的验证

出柜前核对实测柜内/门洞、最大包装外廓、总质量、承压、重心、轴载、地板点载、系固及人员/叉车搬运路径。隔离材料不得挤占模型之外的空间；包装变形、外伸或尺寸超过快照必须重新计算。

系统交付的是可追溯的候选计算和几何校核结果，不能承诺任意订单绝对最优、无空隙或未经实测即运输安全。
