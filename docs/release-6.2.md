# v6.2.0 / MIX 6.2 发布范围与验收记录

## 本版范围

- 只保留“装柜规划”“装柜方案库”。删除批次装箱单、产品包装两个独立页面的组件、导航、入口与专属样式，不再加载这两个模块。规划器自带装箱单及装柜报告出口继续保留。
- 不清空浏览器已有方案及旧模块历史数据；旧数据不再被页面读取。删除的源码可从 Git 历史恢复。历史出货运算辅助库与回归案例保留用于追溯，不构成活跃页面。
- 标准箱毛重直接在产品行输入，净重按业务约定锁定为毛重减 1 kg。批货按克汇总，尾箱按件数比例估算净重并加 1 kg 箱重。未填显示未知，不按 0；不计托盘及外部辅材，不进行柜载荷校验，不是 VGM 声明。
- 所有当前数量、EA/BOX、尺寸和重量均以当前网站输入或用户明确打开的方案快照为准；无 SKU 自动覆盖。默认外箱、托盘尺寸可修改。
- 三维视图保留前壁、箱底和远侧壁三个实体参照面，其余面敞开。参照结构置于有效内腔外，不挤占或改变货物坐标。波纹和塑料托盘结构为示意，非实物结构认证。
- 立体、俯视、侧视、门视按钮在画布前明确显示；默认滚动网页，启用“操作模型”后才接管手势。正交视图禁止自由旋转。蓝色有效边界、琥珀门洞及 L/W/H 尺寸标注区分不同口径。
- SKU 使用不同低饱和色，外箱显示 MEGEE 和实际 SKU/EA 信息；尾箱使用红色胶带。颜色仅为识别，不代表实际印刷。
- 报告三视图改为左侧宽幅俯视/侧视上下排列，右侧门视图；移动端单列。图像由同一场景生成，长视图输出宽 3000px，门视图宽 1800px。
- 数据表遵守 `table-layout-contract.md`：列头与数据同向、数字右对齐、文字左对齐、垂直居中、统一小数位、打印重复表头和逐行防拆。
- 门端纸箱余箱现在同时比较分放与完整支撑混垛，不再因分放能放下就提前停止比较。按内部空隙、占用长度择优；效果相同时优先更简单的分放方式。隔板厚度计入几何高度。
- 40HQ 单托 6 层 / 双托 3＋3 继续作为客户选项，不互相静默替换；20/40GP 的固定 5 层规则不变。

## 本地验证

- `npm run verify`：TypeScript、ESLint、生产构建、112 项回归全部通过；测试运行约 65 秒。
- 浏览器：390×844 手机与 820×1180 平板布局无页面横向溢出；四个视图按钮均至少 44px 高；俯视、侧视、门视可切换；修改计算参数后旧结果失效。
- 纸箱案例：X40401 357000 EA、1000 EA/BOX、7.5 kg/BOX；X40402 357000 EA、600 EA/BOX、7 kg/BOX；均 480×380×350 mm。结果 952 BOX、714000 EA、批货纸箱 G.W. 6842.500 kg、N.W. 5890.500 kg。仅代表该输入案例。
- 托盘案例：两款各 36 箱；单托 6 层为 2 托，名义高 2250 mm、含默认箱差设计高 2268 mm；切换双托 3＋3 后旧结果失效，重新计算为 4 托、每托 18 箱、每地面托位设计高 2418 mm。两款各自三视图均成功生成。
- 混垛回归：两个 SKU 各 4 箱，100 mm 立方箱，3 mm 隔板；混垛与分放均可容纳时，推荐占长从 400 mm 降至 300 mm，数量不变，承压仍待现场复核。
- HTML 报告图像和宽幅排列已目视检查。自动化环境未能打开系统打印窗口，**实际 PDF 分页未逐页验收**；HTML/CSS 检查不是 PDF 验收替代。

## 必须保留的边界

这不是“全部原始愿望均已完成”的声明。当前尚未自动合并跨 SKU 末托；也没有证明全局最优或强制消除每一个内部空隙。真实空隙仍计算、披露并提示处置，不能将有待处置事项的方案视作已批准运输。纸板/PE 膜隔离本身不等于支撑或承压合格。跨 SKU 叠箱和双托必须由现场验证完整支撑、纸箱/托盘承压、门洞及装卸条件；演示只表示顺序，不是搬运路径碰撞验证。

实际输入响应与复杂方案的 P95 耗时未完成性能追踪。构建仍有三维依赖大分包提示；不等于页面始终加载该分包或所有设备都达到同一帧率。

部署须在提交后重建，核对生产版本与构建提交一致。生产发布编号、版本核对和通知结果以发布回执为准。
