# MEGEE Container Planner 6.1

面向订单与现场执行的集装箱装柜生产力工具。工作区为`产品包装`、`批次装箱单`、`装柜规划`与`装柜方案库`。产品资料仅在主动选择后复制到批次；已保存批次与方案不随资料修改而变化。

## 核心能力

- 订单量规划：严格保持各 SKU 输入数量，按 `ceil(EA ÷ EA/BOX)` 计算箱数，尾箱占完整箱位、置顶、禁止承压。
- 柜容反算：支持固定数量、范围可调数量、同组齐套组件数量；每个候选组合都必须通过真实纸箱/托盘排布和几何审计。
- 包装方式：逐 SKU 选择纸箱或托盘。纸箱高度固定向上、底面允许 90° 旋转；托盘显示单托排箱、层数、总高、边界及外伸。
- 标准柜型：20GP、40GP、40HQ。
- 货物实景：不加载集装箱壳体或框架；逐箱显示 MEGEE 牛皮箱标识、SKU 色签与尾箱红色封带，塑料托盘含逐层排箱。
- 多视图：旋转、缩放、装载顺序演示、正交俯视/正视/门视；报告使用同一真实坐标生成的四幅实景，托盘 SKU 另有标准组托三视图。
- 托盘高度：新建40HQ托盘方案由客户选择单托6层或双托3＋3；20/40GP默认5层单托。可明确选择厂内4层、自动搜索或自定义。任何选项均按实际输入与余量校核，失败不会自动切换；承压与操作条件另行确认。
- 计算交互：输入时仅做轻量换算，点击“生成装柜方案”后在工作线程搜索，可取消。改变计算参数立即使旧结果失效；10/60秒为软搜索预算，不是结果或全局最优保证。
- 批次装箱单：独立记录LOT、EA/BOX、外箱尺寸、整箱/实测尾箱毛重和逐托箱号；计算运输外廓CBM及含托盘/辅材毛重，支持批次、柜门、托盘清单和箱标签预览/打印。
- 报告：同一计算快照生成中英文 HTML 装柜报告、打印/另存 PDF 与 Packing List PDF。
- 方案治理：本机方案库、草稿/已确认状态、修订号、搜索、排序及表头漏斗筛选。
- 分享：仅在用户主动操作时生成一个方案的短链接；不会公开本机完整方案库。

默认外箱为 480 × 380 × 350 mm，默认托盘为 1000 × 1200 × 150 mm；EA/BOX 与产品数量不设业务默认值。

## 数据边界

公开版本不含 Cost 系统接口、企业产品快照、Excel 批量预规划、成本、BOM 或客户数据。输入和方案库默认保存在当前浏览器；只有用户主动创建网页分享时，所选方案快照才写入分享存储。

## 本地运行

要求 Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

打开 <http://localhost:3000>。

## 质量门槛

```bash
npm run lint
npm test
npx wrangler deploy --dry-run
```

详细验收标准见 [ACCEPTANCE.md](./ACCEPTANCE.md)，6.1实现与限制见 [release-6.1.md](./docs/release-6.1.md)，原6.0算法见 [loading-algorithm-6.0.md](./docs/loading-algorithm-6.0.md)。

数据源唯一性：当前网页输入是本次计算的依据；SKU 代码不触发历史包装参数覆盖。旧方案只在用户主动打开时恢复其保存的快照。自动化测试是独立测试数据，不能代替业务订单。

离线验收导出必须提供从网页捕获的完整输入，缺失数据会阻止导出：

```bash
node scripts/export-loading-v6.mjs /path/to/website-input-snapshot.json
```

本地验收输出、历史归档和用户输入不进入 Git 或公开站点部署。

## 部署

- 正式入口：<https://container.lostravelerk.com/>
- GitHub 与 Cloudflare 发布必须指向相同提交。
- 页脚、装柜报告与 Packing List 同时显示应用版本、算法版本和源码短提交号。

当前算法是经过边界、间隙、高度、门洞、重叠、箱数、EA 与 CBM 审计的工程规划工具；最终执行仍需现场确认纸箱抗压、托盘承载、总重量、轴载、重心、系固及实测尺寸。
